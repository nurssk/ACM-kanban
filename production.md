# ACM @ NU — проекты, задачи и живые презентации

Обновлено: 1 октября 2026. Заменяет прежнюю концепцию с Keystatic.

## Решение

Используем собственный структурированный редактор презентаций — небольшой предметный CMS внутри приложения. Keystatic не используется. Контент хранится в JSON-структуре с типизированными слайдами; Markdown нужен только для текста, не для конфигурации задач или исполнения кода.

Главная сущность продукта — задача. Её одинаково видят доска, личный список, презентация и будущий Telegram-бот. Внешняя контентная CMS не должна владеть копией тикетов или становиться вторым источником правды.

## Уже работает во фронтенде

- Проекты, доска и список задач, исполнители, статусы, приоритеты, календарные дедлайны, комментарии.
- Библиотека презентаций: поиск, создание, открытие, дублирование, архив, восстановление.
- Единый шаблон `acm-standard-v1`, 16:9, светлый сине-белый ACM-дизайн.
- Ровно три вида слайдов: заголовок, информация, тикеты одного проекта.
- Добавление, дублирование, перемещение и удаление слайдов; Markdown, заметки докладчика, предпросмотр, режим показа.
- Создание/редактирование реальных задач в редакторе и во время показа. Удаление слайда не удаляет задачи.
- Удаление задач из презентации с подтверждением и восстановлением через «Удалённые» проекта. Комментарии и номера сохраняются; задача исчезает из всех активных представлений.
- Автоматическая плотность карточек и страницы для больших списков.
- Автосохранение презентации через 700 мс; явный статус записи; черновик в sessionStorage; предупреждение при закрытии с несохранёнными изменениями.
- Версии сущностей, конфликты вместо тихой перезаписи, журнал изменений, JSON-бэкап пространства, проверяемый импорт с резервированием предыдущего состояния.
- Два источника данных: localStorage и HTTP API. API-режим не откатывается молча на демоданные.

Это локальный MVP, не готовый многопользовательский сервер. Пока нет авторизации, серверных прав доступа, развёрнутого Cloudflare API и отправки сообщений в Telegram. JSON — резервная копия/обмен данными, не PPTX или PDF.

## Составление презентации

1. «Презентации» → «Новая презентация»: название и проект первого слайда задач.
2. Создаются три стартовых слайда: титульный, информационный и задачи выбранного проекта.
3. Слева — порядок слайдов; в центре — шаблон; справа — свойства.
4. Каждый слайд выбирается из трёх типов. Произвольных HTML/MDX, виджетов и свободного рисования нет.
5. Несколько проектов в одной презентации допустимы, но каждый получает отдельный слайд: титул → повестка → сайт → встреча → итог.
6. «Показать» сначала сохраняет изменения. Кнопки/стрелки переключают слайды, Escape завершает показ. Заметки скрыты до нажатия «Заметки».

| Тип | Редактируемые поля | Источник |
| --- | --- | --- |
| `title` | Заголовок, подзаголовок, заметки | Слайд |
| `text` | Заголовок, Markdown, заметки | Слайд |
| `tickets` | Заголовок, один проект, статусы, исполнитель, заметки | Общие задачи проекта |

Markdown: абзацы, заголовки, списки, жирный текст и встроенный код. HTML не исполняется. Текст вписывается автоматически; длинные материалы лучше разбивать на несколько слайдов, а не читать уменьшенный текст. На телефоне доступны свойства, но презентационный шаблон рассчитан прежде всего на большой экран.

### Живой слайд задач

Сохраняются только `projectId`, `statuses`, `assigneeId` и оформление. Названия, статусы и дедлайны тикетов не копируются в презентацию. Дубликат деки копирует структуру, но ссылается на те же задачи.

По умолчанию показаны «К выполнению», «В работе», «Проверка». Бэклог и готовые включаются в свойствах. Сортировка: приоритет → ближайший дедлайн → идентификатор. Задача, скрытая фильтром после редактирования, остаётся в проекте. При фильтре по человеку новую задачу тоже нужно назначить этому человеку, иначе она не войдёт в текущую выборку.

В форме создания проект зафиксирован проектом слайда. Карточка открывает общую форму задачи. Недоступный проект показывает отдельное состояние, без подстановки задач другого проекта.

### Масштаб

Шаблон 1280×720 масштабируется под экран. Плотность определяется самой длинной колонкой:

- До 4 карточек — обычные карточки с исполнителем и сроком.
- 5–7 — компактные.
- 8–12 — плотные строки, часть вторичных полей скрыта; полные сведения доступны по нажатию.
- Более 12 — страницы задач на том же слайде. Счётчик отражает всю выборку; каждая задача достижима.

Не обрезаем данные и не уменьшаем шрифт бесконечно.

## Хранение

Проект → задачи. Презентация → упорядоченные слайды. Слайд задач → один проект. Нет каскадного удаления задач через презентацию.

- `issue.id`: стабильный технический ID для API/бота. Новые записи — UUID, старые ID сохраняются.
- `identifier`: читаемый номер WEB-25, не ключ связей. В production номер атомарно назначает сервер.
- `version`: версия сущности для конкурентного редактирования.
- `revision`: монотонный номер состояния пространства.
- `createdAt/updatedAt/occurredAt`: UTC ISO 8601; в production — серверное время.
- `due`: YYYY-MM-DD или null; календарная дата, не UTC timestamp. Напоминания рассчитываются по timezone клуба.
- `assignee`: ID участника или null, не имя/Telegram username.
- `events`: изменения с commandId, actorId, версией, проектом и before/after.

Локально сущности, события и квитанция команды сохраняются одним JSON-записыванием в `club-os-workspace-v2`. Старые ключи `club-os-*` оставлены для восстановления. Повреждённые данные не заменяются демоданными. При переполнении хранилища показывается ошибка, не «сохранено».

LocalStorage — прототип на одном origin/браузере, не облачный бэкап и не база бота. Перенос с localhost на 127.0.0.1 или другой порт требует экспорта/импорта. Журнал растёт: для большого архива и многопользовательской работы нужен API, а не этот локальный режим.

## Сохранение и конфликты

Задачи сохраняются явно; презентации — автоматически и по кнопке. Пока идёт запись, связанные элементы редактирования недоступны. Ошибка оставляет форму/черновик на экране. Новая версия не затирает несохранённый текст: можно скачать черновик и загрузить актуальную запись.

Перед HTTP-запросом команда с UUID попадает в sessionStorage. После неоднозначной сетевой ошибки/5xx «Повторить отправку» использует тот же ключ идемпотентности, в том числе после перезагрузки той же вкладки. До подтверждения другие записи блокируются. Закрытие всей вкладки может уничтожить sessionStorage; сервер дополнительно проверяет уникальность ID сущности/комментария. Это не полноценная offline-first очередь и не посимвольное совместное редактирование.

UI принимает подтверждённый сервером snapshot. API обновляется раз в 15 секунд в видимой вкладке и при возвращении фокуса. WebSocket/SSE можно добавить позже в слой репозитория. Локально — storage events и Web Locks, где доступны; полноценные гарантии конкуренции даёт сервер.

## Cloudflare и Telegram

Рекомендуем: Worker API → D1. Фронтенд обращается только к Worker. D1 binding, токен бота, серверные права и очередь не попадают в браузер.

Worker фиксирует задачу, событие, receipt и outbox атомарно. D1 поддерживает транзакционные batch-операции; ошибка откатывает пакет. Это архитектурное решение, не уже реализованный сервер. [D1Database](https://developers.cloudflare.com/d1/worker-api/d1-database/).

Уведомления отправляются после commit. Cloudflare Queues допускает повторную доставку, поэтому нужны дедупликация и проверка состояния. [Queues delivery guarantees](https://developers.cloudflare.com/queues/reference/delivery-guarantees/).

Напоминания запускает сервер, не открытая вкладка. Подходит scheduled handler Worker. [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/).

Предлагаемые события: назначение, изменение срока, комментарий, напоминание о дедлайне. Правила и согласие на уведомления утверждает клуб. Telegram-аккаунт привязывается к member ID через одноразовую ссылку; искать человека по имени нельзя.

1. Реализовать Worker, auth и серверные права; проверить конкурентные записи на D1.

3. Подключить API через .env.local; согласовать login/401 с провайдером авторизации.

5. Проверить резервирование/восстановление D1, мониторинг и нагрузку на реальном объёме.
